# 收货功能 SQL 执行说明

整理日期：2026-11-16。本会话仅整理脚本，未连接或修改真实数据库。

## 直接执行哪份

选中现有 Web 使用的 MySQL 数据库，执行整个 **`receiving_pending_all.sql`**。该文件已经依次包含 022、023、024 及执行后检查，不需要再逐份执行。兼容 MySQL 5.7+，使用 UTF-8 打开。

文件不预设数据库名称。执行前确认 `SELECT DATABASE()` 是 Web 正在使用的业务库；不要选系统库。需要具有建表、追加字段和索引的权限。保留现有数据库备份，先完成结构变更再发布使用这些字段的 Web/PDA。

## 内容与优先级

| 来源 | 数据结构 | 用途 |
| --- | --- | --- |
| 022 | `carrier_settings`、`carrier_receiving` | 承运商配置及包裹实收/对账 |
| 023 | `receiving_sync_settings`、`bluetti_receiving_forecasts`、`receiving_sync_runs`，以及追加查询字段/索引 | 站点范围、BLUETTI 预报与定时查询 |
| 024 | `carrier_receipt_scans` | PDA 人员、设备、批次、原始条码、扫码和上传时间 |

合并版包含P0收货及P1同步基础表，不代表P1完整看板已经交付。2026-11-19起，P0直接采用已登录账号的域，不再读取023的预报站点配置；无预报也能收货，客户同步和自动查询可保持关闭。脚本不预填账号、密码、域或站点。

P2 维修 checklist 和 P3 个人任务 Dashboard 暂不建表。软件权限由现有 Web 角色代码控制，本轮不需要另插权限或创建管理员账号；账号和会话等既有基础表仍沿用原部署。

## 重复执行与错误处理

- 新表使用 `CREATE TABLE IF NOT EXISTS`，不会清空旧表。
- 023 添加字段与索引前检查 `information_schema`，已存在时跳过，支持部分执行后重试。
- 不自动修改同名但定义不同的字段或索引；这类情况需要核对 `SHOW CREATE TABLE`。
- MySQL DDL 会隐式提交，整份文件不是一个可回滚事务。出现第一处错误时停止，保留完整错误及执行位置，不要忽略错误继续。
- 本文件未在目标 MySQL 实例执行过；名称检查通过也不代表真实接口、人员登录或 PDA 已经验证成功。

## 怎么判断执行完成

合并文件末尾会返回结构检查：6 张表都应显示 `OK`；缺失字段、缺失索引两张结果表均应为空。检查只查询结构元数据，不展示凭据或业务数据。

也可单独执行 **`receiving_verify.sql`**，不需要再次运行建表脚本。若有 `MISSING` 或前面任何 DDL 报错，先处理后再发布。此检查只核对名称，不核对已有类型、字段默认值或索引列顺序。

执行后：发布 Web → 管理员保存站点/凭据 → 更新 PDA → 登录原收货账号，验证一件包裹扫码、确认及重复上传。保留部署目录下 `App_Data/carrier-keys`，避免原有加密凭据无法解密。

## 维护合并脚本

编号脚本是结构来源，不在合并版重复手改：

```powershell
pwsh -NoProfile -File tools/BuildReceivingSql.ps1
pwsh -NoProfile -File tools/BuildReceivingSql.ps1 -Check
```

生成器只读写仓库内 SQL 文件，不连接数据库；`-Check` 检查合并版和只读检查是否与编号脚本一致。上述命令使用允许执行项目脚本的 PowerShell 7 终端；若本机执行策略禁止脚本，无需为执行 SQL 改变策略，直接使用已经生成的 SQL 文件即可。
