# 收货SOP

本 SOP 供经理使用，目标是将仓库收到的货物登记到共享表格 **“美国Logistar仓收件登记表-更新版9.02”** 中。

## 操作范围

收货和入库是两个独立过程。本 SOP 只记录经理的收件登记操作，WPF 入库流程另行整理。

## 1. 在 WPF 扫码录单

经理需要把收到的货物整理成收件记录。核心是两件事：**记录对应的物流单号和设备 SN，并标注退件类型。** 同时填写仓库收件日期和机型。

在 WPF 功能组打开“扫码录单”，按下面顺序处理每个包裹：

1. 先扫描箱子上的运单号。
2. 开箱。
3. 扫描设备 SN。
4. SN 自动匹配成功时，系统会打印 label。
5. 匹配不上时，系统会弹框询问类型，按实际情况选择类型。

每个包裹都先扫运单，再扫箱内设备的 SN，通过自动匹配或弹框选择确定类型。

## 2. 选择登记页

打开共享表格“美国Logistar仓收件登记表-更新版9.02”，根据货物来源选择对应页面：

- **亚马逊**：在“亚马逊收件登记表2025”页登记。
- **无源头／eBay**：在“eBay&无源头退货登记表2025”页登记。

页面名称和退件类型是两回事。进入“eBay&无源头”页，不代表所有货物都应填成 EBAY；类型按实际确认的信息填写。

## 3. 填写记录

按设备逐条登记。一个包裹内有多台设备时，分别记录各自的 SN，并填写对应的同一物流单号。

| 字段 | 填写内容 |
| --- | --- |
| 仓库收件日期 | 实际收到货物的日期 |
| 机型 | 对应设备型号 |
| SN | 对应设备的完整 SN |
| 物流单号 | 这台设备对应的完整运单号 |
| 退件类型 | 根据实际来源或已确认的工单信息填写 |

物流单号和 SN 按文本填写，保留完整字符及前导零，避免长号码被表格转成科学计数法或改变末尾数字。

## 4. 完成共享表格登记

检查本次记录的 SN、物流单号及类型是否对应，再确认内容已保存到共享表格。本 SOP 到收件登记完成为止，不以 WPF 入库完成作为结束条件。

截图中的“是／否”和“售后系统收件日期”属于另外的信息，不能仅凭货物已到仓就认定已录入售后系统。它们的填写责任和更新时机待进一步确认。
