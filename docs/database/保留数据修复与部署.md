# 保留线上数据的修复与部署

更新：2026-10-10。已完成代码和迁移文件，**未连接线上库执行**。基线快照保留原样，不能将其当迁移脚本运行。所有业务数据保留：良品区重复记录和上架记录仅标记归档，不物理删除；原历史时间、已有审核位、账号和会话不批量重写。

## 1. 已实现行为

- 有效良品区 SN 大小写不敏感唯一，原 SN 字符串大小写不变；旧重复行标记 duplicate 归档，保留全部行。
- 上架标记有效良品区行为 shelved 归档，不 DELETE；工单仅当前周期的 audit_status=0 改为 1，不覆盖其他状态。
- 上架需要 requestId；桌面/Mac 共用客户端记录未确认请求到本地磁盘，重启同内容重试复用 GUID。服务端保存内容哈希和回执，同 GUID 不同内容拒绝，成功重试不再次插入、改状态或发飞书通知。
- 扫描 GUID 回执独立保存；原请求重放不重新进入良品区。新扫描 GUID 在已上架状态开启新周期，允许售出后返修。同一有效周期内旧时间扫描不覆盖较新的托盘归属。
- 自动匹配携带 cycleNumber，旧周期上传拒绝；已上架周期不新增待办。第一周期保持已有来源键，后续周期来源键隔离。
- PDA 良品区及 SKU/SN 的 SN 去重不敏感，保存原值；库位 ID 规则不变。历史批次不自动清理或重写，新批次中的大小写重复 SN 不允许新增。
- 工单接收账号可用 WorkOrders__DefaultUsername 配置，默认 my9281；客户端不再写死返回用户名。
- 数据库连接设 UTC session time_zone；不转换旧 DATETIME 值，上架业务本地日期规则保持不变。
- 库位状态管理 PUT /api/warehouse-locations/status，Bearer + system.configure，提交 locationId、isDisabled、reason，操作者从认证身份取得，状态和审计记录同事务。
- 批次下载校验明细条数与 item_count，发现不一致报错，避免静默使用残缺数据。
- 凭据版本校验使旧会话失效；015 的改密触发器在密码材料变化时自动增加版本，避免同秒时间比较漏洞。不会物理删除旧会话。

## 2. 部署顺序

1. 在测试库恢复一份现有数据备份，先运行 [只读检查](repairwms-review-checks.sql)。记录表总行数、重复 SN 数、大小写/重音碰撞、账号/外键有效性。不要运行旧 002 的 DELETE 去重。
2. 停止 PDA 上传、工单生成和上架写入，保留当前部署包和完整数据库备份。不要在旧 Web 仍写入时执行迁移。
3. 已有 location 列时不需再次添加；否则先执行 010。依次执行 011、012、014、015；013 是性能可选项，先 EXPLAIN 再选择。脚本在 [Database](../../Scanner.Web/Database)。015 触发器首次创建，重复部署先检查 SHOW TRIGGERS；不自动删除现有触发器。
4. 核验新列、有效 SN 唯一索引、迁移记录和触发器。011 前后 tester_pallet_scans 总行数应相同，只有有效/归档分组变化。012 不根据历史上架强行回填工单审核位，有效良品区优先初始化为未上架。
5. 部署新版 Web、WPF/Mac 和 PDA，再恢复写入。旧桌面缺 requestId 会拒绝上架，提示升级；第二及以后周期旧自动匹配客户端也会要求重新下载。不要只升级客户端或只跑一半迁移。
6. 用测试记录执行：重复大小写扫描、并发同 SN；上架超时/重启重试；上架后旧 GUID 重放；同 SN 新 GUID 返修和第二次上架；旧周期工单上传/保存冲突；改密使旧会话失效；库位禁用原因及权限。

DDL 隐式提交，失败停止检查后续，不能假设整包事务回滚。015 触发器需 TRIGGER 权限，迁移账号和应用账号分开。migration_id 是部署记录，不会自动跳过整个脚本。

## 3. 回退与兼容

优先回退应用前停止写入，使用部署前完整备份恢复到隔离测试库核对；线上恢复需同时保留部署后的新业务记录，不能直接覆盖备份造成丢失。新字段和辅助表可继续保留，禁止为了回退 DROP TABLE。旧应用不会过滤 is_archived，直接回退会再次显示历史行，所以需要保留归档过滤补丁或完成专门回退方案。

011 若检测到旧 uq_tester_pallet_sn，将替换为有效行唯一索引，仅移除索引不删数据。SN 比较沿用 utf8mb4_unicode_ci 的不敏感规则，涵盖的不只是 ASCII 大小写；非 ASCII 编号/重音碰撞需先预检，无法确认时停止迁移。历史良品区采用扫描时间最新、相同时间 id 最大者为有效行，其余完整保留可复核。

本地未确认请求保存在用户 LocalApplicationData/Scanner/shelving-requests，只存 GUID；不要在尚未核验服务端结果前手动清除。同内容修改后视为新请求，不能借修改列表来重试旧请求。库位管理 API 不增加平板管理页面，已有七个占位入口不因此视为业务完成。
