# 系统使用与维护手册

更新：2026-10-21。适用于壹仓 WPF、Scanner.AndroidTester PDA、CheckListBoard 平板及 Scanner.Web。本文依据仓库配置和代码编写，安装、数据库迁移及真机验收需由维护人员执行；本次未操作生产环境。

## 1. 安装哪些组件

| 场景 | 安装或准备内容 |
| --- | --- |
| 仓库电脑 | WPF 发布目录、按发布模式准备运行时、扫码枪及打印驱动 |
| 良品区 PDA | Scanner.AndroidTester 的正式签名 APK；不要误装 Breezary 扫码入库应用 |
| 检测平板 | Scanner.CheckListBoard 正式签名 APK、服务器地址和业务账号 |
| 服务端 | Scanner.Web 发布包、HTTPS 站点、MySQL、运行环境、持久存储及备份 |
| Breezary / Mac | 按对应专项文档单独部署，不作为普通良品区操作的必装项 |

工程与职责见 [工程总览](项目结构审计.md)。操作人员使用已交付的安装包，无需安装开发 SDK；源码构建人员才需 .NET 10 SDK、MAUI/Android 工具链或 Apple 工具链。

安装前由维护人员登记：环境名称、服务器 HTTPS 根地址、客户端/服务端版本、数据库名称、设备型号与架构、签名来源、维护联系人。密钥和密码通过受控渠道交付，不填入共享文档或验收截图。

## 2. 首次安装顺序

顺序：数据库准备 → 服务端配置与启动 → 账号初始化 → WPF/PDA/平板安装 → 基础数据准备 → 测试闭环 → 正式交付。已有系统升级使用第 8 节，不用空库初始化方式覆盖现有库。

### 2.1 新数据库初始化

1. 维护人员创建独立空库和访问账号，核对字符集、时区、权限及备份位置。当前现场基线为 MySQL 5.7.17，脚本要按此基线验证，不仅凭文件名执行。
2. 在已选择的空库导入 [2026-10-09 纯结构快照](database/repairwms-schema-2026-10-09.sql)，形成基线的 11 张表。它不带业务数据、域或账号，也不包含后续全部功能表。
3. 核对工单 location 等基线字段，按 [保留数据修复与部署](database/保留数据修复与部署.md) 在测试环境验证后执行 011、012、014、015；013 为可选索引。已有 location 不重复执行 010；已有表不重复用 001–010 重建。不要运行含 DELETE 去重的旧 002，也不要把 005 样例导入正式库。
4. 016 是基于已有 11 张表的合并迁移，不是空库初始化脚本；内部固定 USE repairwms。使用前逐项核对目标库与现有结构；选择分步迁移或经核验的合并方案，不将两套当作都要执行的步骤。
5. 仅使用 Breezary 功能时，另按专项说明核对 017、018、019；普通良品区不要求开通腾讯文档授权。执行情况记录脚本名、执行人、时间和核验结果。
6. 核对有效 SN 唯一索引、扫描回执、设备周期、上架请求回执、凭据版本及触发器等结构。新建空库同样需要具备新版服务依赖，不能停留在旧快照。

DDL 可能隐式提交，出错时停止检查，不能按整包事务已回滚处理。应用不会自动完成上述初始化。

### 2.2 服务端配置与安装

1. 维护人员生成 Scanner.Web Release 发布目录，部署至已准备的服务器站点；保留发布包内 Documentation 和网页资源。可在仓库根目录构建：

```powershell
dotnet publish Scanner.Web/Scanner.Web.csproj -c Release -o artifacts/web-initial
```

2. 按发布模式安装兼容的 ASP.NET Core .NET 10 运行环境；IIS 托管需对应托管组件，应用池配置与目录权限由服务器维护人员核验。该命令生成发布文件，不自动创建站点、证书、数据库或服务。
3. 配置 HTTPS 域名、证书、站点启动及反向代理。现场默认地址为 https://wms.ymforever.com/；测试环境使用维护人员分配的地址，所有设备必须对应同一环境。
4. 将实际配置通过环境变量或受控的 appsettings.Local.json 提供。该本地文件不随常规发布复制，迁移服务器时须单独受控交付；不要依靠源代码包携带生产凭据。

| 配置组 | 核对项目 |
| --- | --- |
| Database | Enabled=true；Server、Port、Database、UserId、Password；按现场要求核对 SslMode |
| Upload | ApiKey、Directory、MaxBytes、MaxPreviewBytes；客户端上传密钥须匹配；目录可写 |
| WorkOrders | DefaultUsername，默认 my9281；接收账号必须存在、启用并属于启用域 |
| WpfUpdates | StoragePath，建议站点外持久目录；更新发布账号及目录写权限 |
| FeishuRobot | 可选通知配置；是否启用由维护人员登记 |

环境变量用双下划线，如 Database__Password、Upload__ApiKey、WorkOrders__DefaultUsername。业务数据目录和更新包目录需要发布后保留，覆盖站点时不得清空。

5. 启动站点，访问 /health 确认进程响应；维护人员携带上传密钥检查 /health/database。前者成功不代表数据库、表结构和业务事务全部正常。
6. 继续执行账号初始化及第 7 节验收后开放正式使用。不要通过关闭鉴权解决登录或上传失败。

### 2.3 首个管理员及工单接收账号

公开注册入口保持关闭，当前没有已交付的一键首管初始化流程。由获授权的数据库维护人员按 [账号与会话说明](../Scanner.Web/WEB_LOGIN.md) 初始化：先建立启用的 user_domains，再建立合法 app_users 记录，使用 UTF-8 PBKDF2-SHA256、随机盐、二进制哈希及匹配的迭代参数，角色为 admin，账号状态为 active；不得把明文密码直接写入哈希字段。

另准备普通操作账号和只读账号，并核对工单接收账号。管理员浏览器登录与平板登录使用这套 Web 账号；WPF 主登录沿用其现有认证流程，不因 Web 建好账号就默认可登录 WPF。没有有效 WPF 登录信息时联系维护人员；本地扫描模式不证明服务器或上传已授权。

交付前分别验证 admin/user/viewer 权限、退出后会话失效、工单接收账号能看见自己的任务。管理员身份不代表可以通过平板工单接口读取他人的任务。

## 3. Windows 工作台首次安装

1. 获取维护人员交付的完整 WPF 发布包，解压到当前用户可写的固定目录；不要仅拷贝 EXE，也不要在压缩包内运行。
2. 依赖框架的 win-x64 包需要 .NET 10 Windows Desktop Runtime x64；自包含包按交付说明运行。完整发布方法见 [WPF 发布与自动更新](WPF发布与自动更新.md)。
3. 关闭应用后核对发布目录 Scanner.WPF.dll.config（如交付包使用 exe.config，同时核对实际配置）：UploadBaseUrl 指向目标环境，UploadApiKey 与服务器一致；自动更新地址与开关按维护方案设置。
4. 接上扫码枪，设置为键盘输入并以 Enter 结束，在普通文本框试扫核对前导零、完整内容及一次扫描只提交一次。
5. 安装打印机驱动，核对默认打印机、纸张规格与方向；用测试标签验收清晰度及二维码可扫性。不要仅凭“发送成功”判断实际出纸正确。
6. 启动 WPF，按已有认证方式登录，进入“基础数据 → 导入基础表”，核对文件来源和日期。基础表缓存按应用生命周期存在，重启后重新核对/导入；导入失败可能保留旧缓存，须核对显示的文件路径。
7. 验证查看良品区、自动匹配及测试标签；正式上架另按 [上架 SOP](sop/上架SOP.md) 执行。安装验收不要上传正式设备来测试。

## 4. PDA 首次安装与配置

1. 确认使用 Scanner.AndroidTester；最低 Android API 24，架构与交付包一致。正式分发使用既定生产签名，记录版本与设备编号。
2. 首装按设备管理要求允许对应来源安装，将维护人员交付的 APK 安装到 PDA；升级应保留应用标识、签名及版本关系，不通过卸载旧版解决覆盖失败。
3. UploadBaseUrl 与 UploadApiKey 位于嵌入的 appsettings.xml；普通 PDA 没有现场输入上传密钥的设置页。地址或密钥变更须重新打包安装，见 [PDA 配置](../Scanner.AndroidTester/APPSETTINGS.md)。不将 Breezary 应用的“连接设置”套用到本应用。
4. 连接现场网络，校准日期、时间和时区。扫码枪采用键盘输出、Enter 结束；输入框试扫完整 SN，核对不是运输单号或 SKU。
5. 首页默认英语，可切换 English / Español 并记住选择；中文 SOP 中的按钮对应见 [良品区 SOP](sop/良品区操作SOP.md)。
6. 用指定测试 SN 和托盘验证记录、上传及 WPF 刷新结果。完成测试数据的受控处置后再交付设备。
7. 仅使用蓝牙打印时，再配对容大 RP425、授予蓝牙/附近设备权限并核对 TSPL/ZPL，见 [PDA 打印](AndroidTester打印.md)；普通扫码上传不要求配对打印机。

源码打包参考 [MAUI 包体与发布](MAUI包体优化.md)。安装包签名密钥、正式分发位置和安装授权由现场维护人员交付。

## 5. 检测平板首次安装

1. 安装 Scanner.CheckListBoard 的正式签名 APK，核对应用和环境，不误装 Breezary CheckBoard。
2. 登录页打开“服务设置”，填写正确 HTTPS 地址；使用已初始化的 Web 业务账号登录，不能用设备上传密钥代替密码。
3. 共享设备按管理要求决定是否记住凭据。保存凭据使用 SecureStorage；会话仅在内存，重启仍需登录。
4. 核对账号权限、工单位置、下载结果和操作文档；工单只下载当前用户且审核位为 0 的记录。空列表先检查账号归属、分配和审核状态。
5. 修改完成状态后点击保存，逐项确认已保存；部分失败保留未成功项，版本冲突需重新下载核对，不能只切换开关后直接离开。

完整行为见 [平板说明](../Scanner.CheckListBoard/README.md)。其他待接入检测入口不能当作已可用模块。

## 6. 日常使用与数据保护

| 数据/状态 | 当前保存方式 | 操作要求 |
| --- | --- | --- |
| PDA 良品区、库位待上传记录 | 内存，上传确认后移除；本次运行去重仍保留 | 上传前不强退、重启、升级、清数据；点“完成”只是返回页面，不是上传 |
| PDA SKU/SN 批次及半对 | 应用私有文件；封存后按原批次重试 | 不卸载或清应用数据；上传确认前保留原批次 |
| WPF 基础表 | 当前应用容器缓存 | 重启重新导入；确认来源和版本，不把 PDA 批次当基础表 |
| WPF 未确认上架请求 | LocalApplicationData/Scanner/shelving-requests | 未查明服务端结果前不删除；同内容原请求重试 |
| 平板工单修改 | 页面待保存状态，逐条保存到服务器 | 离开前确认保存结果；未保存内容不是数据库记录 |
| 服务端业务、账号与回执 | MySQL；更新包和上传文件另存目录 | 备份数据库及持久目录，不只备份程序文件 |

班前核对网络、设备时间、环境地址、待上传数据和基础表版本。班末停止新增扫描，处理所有未确认上传，WPF 刷新复核，平板保存待修改工单，再按交接要求退出。

良品区扫描、SKU/SN 扫描及库位扫描是不同用途：前者记录 SN 托盘归属，第二种为上架准备配对批次，第三种登记库位主数据。只有登记库位不会把货物移到该库位。

## 7. 首次交付验收

使用隔离环境或批准的测试记录，记录版本、设备、执行人、时间、结果与异常：

- [ ] HTTPS、/health、受鉴权的数据库健康检查均符合预期；正式库结构与迁移记录核对完成。
- [ ] 管理员、普通和只读登录权限正确；接收账号能下载分配工单。
- [ ] PDA 一箱一扫 SN，上传后 WPF 刷新可见正确托盘、SN 和数量。
- [ ] 断网后待上传保留，恢复网络原记录重试，刷新无重复有效 SN。
- [ ] 良品区换托测试后，源托减少、目标托增加且总量不变；未把已上架货物作为移库测试。
- [ ] WPF 基础表匹配、测试标签实际出纸及复扫正常，平板修改获得保存确认。
- [ ] 文档入口可阅读文字、截图和附件。
- [ ] 正式上架测试另按已确认的现场顺序执行，记录上架回执、工单过滤与良品区归档；尚缺的现场规则不由安装验收代替批准。

## 8. 升级、备份与故障处理

### 8.1 升级与回退

升级前保存当前发布包、配置、数据库及持久目录备份，登记版本；先在测试环境验证迁移和客户端兼容。PDA 良品区/库位全部上传并核对后才能重启安装；SKU/SN 也应尽量完成确认，不卸载清数据。

涉及数据结构升级时，暂停相关 PDA 上传、工单生成和上架写入，按 [保留数据部署步骤](database/保留数据修复与部署.md) 执行。服务端与客户端协同升级：旧客户端缺少上架 requestId 等字段会失败，不能只升一侧。WPF 自动更新保留本机配置，地址或密钥变化仍需维护人员核对，不会因程序升级自动替换成本次新值。

回退先停止写入并评估新旧结构兼容；不通过删表、清库恢复旧版本。备份先恢复到隔离库验证，正式恢复需处理备份之后的新记录，不能直接覆盖丢失业务数据。

### 8.2 备份与交接

维护清单应包含数据库完整备份及恢复验证、站点外上传目录、WPF 更新包持久目录、服务端配置、客户端发布配置、签名材料的受控保管，以及原始基础表/扫码文件/清单。密码和签名密钥单独受控保存。

备份频率、保留期限、恢复时间目标、值班联系人和故障升级时限尚未由现场确定，须补录后形成正式运维交接表。没有恢复演练记录，不能仅凭“已生成备份文件”视为可恢复。

### 8.3 常见故障

| 现象 | 先处理什么 | 结束条件 |
| --- | --- | --- |
| /health 正常但业务失败 | 检查 Database 配置、受鉴权健康检查、结构/迁移和应用日志 | 测试业务成功，不能仅凭主页可打开 |
| PDA 上传失败或密钥错误 | 保留当前应用和待上传；核对网络、环境地址及嵌入密钥 | 原记录获得确认，WPF 刷新可见 |
| PDA 换托时提示重复 SN | 本次运行去重未清除；按良品区 SOP 先核对并处理完所有待上传，再结束旧进程开始新作业 | 新目标托盘上传及源/目标双向核对通过 |
| 上架超时或回执异常 | 保留原数据和本地请求记录，查询服务器并按原请求重试 | 回执及服务端记录核对一致；不能随意改内容重新上传 |
| 平板工单不见 | 核对当前账号、任务归属、审核位和上架结果 | 确认应显示的任务范围；不盲目重新生成工单 |
| 平板保存冲突/部分失败 | 保留未成功项，核对版本，按提示重新下载或重试 | 所有本次修改明确为已保存或已放弃 |
| 打印无纸/错纸/二维码不可扫 | 检查驱动、纸张、方向、设备语言和实物出纸 | 测试标签实际复扫成功，错误旧标签作废 |
| WPF 更新失败 | 查看 %LOCALAPPDATA%/Scanner/Updates/update.log、安装目录写权限及占用 | 确认实际启动版本；业务数据和配置完整 |

报障记录保留操作时间、设备、版本、环境、操作步骤、错误文本及涉及 SN/托盘；截图不带密码、上传密钥或令牌。误上架、错误归属、账户初始化失败由指定维护人员核查，不由操作人员直接改库。

## 9. 仍待补齐的交付流程

| 待补项 | 目前边界 |
| --- | --- |
| 首个管理员初始化交付 | 有密码格式和表结构依据，缺经现场验证的一键工具及实际交接步骤 |
| 安装与升级分发 | 缺正式安装包存放位置、签名保管人、设备安装授权和统一版本台账 |
| 网络与服务器交接 | 缺站点/证书/服务维护人、备份恢复演练、告警与故障时限 |
| 基础表管理 | 缺来源、更新频率、版本命名、审核及异常处理责任 |
| 现场流程 | 移库审批与记录、已生成工单的位置变化、正式上架确认交接仍需明确 |

这些内容按已确认的现场资料补录，不在本文填写虚构账号、默认密码或未验证的生产部署结果。
