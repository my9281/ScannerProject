# Camara.WPF 标签数据序列化

## 已保存的数据

默认数据已整理为 UTF-8 JSON 文件 [label-data.json](../WPF.Camara/Data/label-data.json)，版本 `schemaVersion: 1`，由程序嵌入加载。

| 数据区 | 内容 | 当前规模 |
| --- | --- | --- |
| `forecastRows` | 核对明细：行号、托盘分组、原始码、数量、校正条码、SKU | 第二批 66 行，261 件，均可打印 |
| `labelCatalog` | 原批量贴标清单：SKU、核对码集合、数量 | 第二批 66 项，261 件（保留各条码独立记录） |
| `cameraModels` | 型号规格：型号、功能标志、规格后缀列表 | 14 个型号 |

这三部分是不同用途的数据，数量不能相加当作库存。所有编码均为字符串，保留前导零、大小写、连字符及未知 SKU 标识；不合并重复行，不推测校正码。原始 TSV 文件保留作来源核对，默认加载改用 JSON。

## 保存当前窗口的数据

点击主窗口右上角“导出标签数据”，选择 JSON 保存位置。

- 导出全部当前核对明细，包括所有托盘和散货组，不局限于选中的托盘。
- 已通过原有 TSV 导入临时载入的数据也会被导出。
- 原批量贴标清单中修改过的数量会先提交编辑，再一起保存。
- 型号配置同时保存；可打印状态、界面提示和打印页数由原有规则重新计算，不作为源数据写入。
- 导出不会修改程序默认数据，也不会自动打印。未成功保存时保留当前窗口数据。

程序启动仍加载内嵌的 `Data/label-data.json`，外部导出文件是快照，不会在下次启动时自动覆盖默认值。当前没有新增 Excel 或外部 JSON 导入按钮；现有 TSV 导入继续可用。

## 字段约定

| 数据区 | 字段 | 说明 |
| --- | --- | --- |
| 明细 | `line` | 既有明细行号，导出保留顺序；当前第二批为 1–66；历史数据为合并后的全局行号 |
| 明细 | `pallet` | 正数为托盘编号；负数为逻辑分组，`-1`/`-2` 为旧散货组，当前 `-3` 显示为“第二批”，不表示实际托盘号 |
| 明细 | `originalCode` | 原始产品码 / 原表中的码 |
| 明细 | `barcode` | 标签一维码使用的校正码，与原始码分别保存 |
| 明细 | `sku` | 完整 SKU，保持原文 |
| 明细、清单 | `quantity` | 0–999 的整数 |
| 清单 | `checkCodes` | 原清单中的核对码文本，可能含多个码 |
| 型号 | `sku`、`specifications` | 型号前缀和规格后缀，组合规则沿用原程序 |
| 型号 | `transmitter`、`detector`、`whiteBalance`、`speaker` | 原程序的功能标志，含义和打印规则不变 |

## 后续 Excel 导入

收到实际 Excel 后再确定工作表、表头、字段映射及是否追加或替换。优先把 Excel 转换为相同的数据结构，再供核对、打印和导出使用。

需要保留来源文件、原工作表和原行号的扩展字段时，应升级格式或明确兼容规则，不能把当前全局行号误认为 Excel 原行号。型号规格不从相近 SKU 自动推断，未知信息继续保留待核对。

## 第二批与历史数据

本轮按用户提供的条码/FNSKU、完整 SKU、数量逐行录入第二批，合计 66 行、261 件、60 个不同 SKU。不同条码对应相同 SKU 时不合并，SKU 大小写保留（包括 `20m`）。原始码与标签一维码均使用用户本次给出的条码；原批次的校正映射不会覆盖本批输入。

当前 `label-data.json` 的核对明细和贴标清单均只含第二批。原来的 158 行核对明细和 29 项贴标清单完整归档到 [历史 JSON](../WPF.Camara/Data/history/label-data-before-batch2-2026-11-14.json)，不自动加入当前打印任务。型号规格作为共用基础资料继续保留；新 SKU 未提供的配置不推测。

“查看历史数据”位于核对打印页的导入按钮旁，打开只读明细、贴标清单及规格窗口，不替换当前数据。历史 JSON 随程序复制到 `Data/history`。本批录入来源另保存为 [batch2-source.tsv](../WPF.Camara/Data/batch2-source.tsv)。
