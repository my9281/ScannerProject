## 用户和密码

- 创建用户：管理员填写用户名、可选显示名称、角色、初始密码与确认密码。只创建在管理员自身所属域，不能指定其他域；用户名遵循现有数据库全局唯一约束。不会替新用户创建会话或改变管理员当前登录。
- 用户列表：仅返回本域的 ID、用户名、显示名称、角色与状态，每页最多100条；可搜索用户名/显示名称。接口不返回密码材料或会话。
- 修改自己的密码：所有已登录角色均可操作，需要当前密码及两次新密码。成功后撤销所有旧会话，页面清除本机令牌并跳转登录。
- 管理员重置密码：从本域列表选择其他用户，输入两次新密码。旧会话撤销；目标账号的停用和锁定状态保持原样。修改自己密码须使用验证当前密码的入口。
- 新密码与现有注册规则一致，至少6个字符、最多4096个字符，不允许全为空白。有效密码的首尾空格不会被去掉。

## 接口和实现

| 方法及地址 | 服务端权限 |
| --- | --- |
| `GET /api/account-management/users?after=0&search=` | `system.configure` |
| `POST /api/account-management/users` | `system.configure` |
| `POST /api/account-management/users/{userId}/password` | `system.configure` |
| `POST /api/account-management/password` | `checklist.read`，覆盖现有三个有效角色 |

服务端在参数校验后使用参数化 SQL。变更时先按用户ID顺序锁定涉及的账号，在事务中重新核验管理员/操作人权限、所属域、账号状态和原会话，再执行变更。重置不能跨域。密码使用随机16字节盐、PBKDF2-SHA256、100000次迭代、32字节哈希，兼容现有登录验证。

修改密码在同一事务更新密码材料、`password_changed_at`、`credential_version`并撤销旧会话；兼容既有密码版本触发器。日志只记录操作人、目标用户ID和域，不记录密码、哈希、盐或令牌。

公共注册入口仍按 `Program.cs` 保持关闭，没有重新开放匿名注册。
