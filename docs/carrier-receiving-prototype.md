# FedEx / USPS 仓库收货对账：需求与实施说明

> 历史原型记录：本文描述早期手工登记与查询实现。最新目标以 [两池、PDA 与看板方案](carrier-receiving.md) 为准，本文不是完整方案的部署说明。

记录日期：2026-11-15。状态：已完成第一版代码与模拟测试，待数据库迁移、部署和真实承运商联调；不代表已上线。

## 业务背景

仓库接收 FedEx、USPS 货物，近期频繁出现疑似丢件。现场通常整板或整批签收，司机并不掌握准确件数，无法在交接时提供可逐件核对的清单。因此，仅记录司机签收或整板数量，无法判断某个包裹是否实际交到仓库。

需要将承运商侧的运单状态与仓库侧的逐件实收记录进行对账，及时发现差异，并保留后续查录像、联系承运商和内部排查所需的时间与人员信息。

“承运商显示已送达”与“仓库确认逐件实收”必须分别记录。差异属于待核实事件，不能直接判定丢件或责任方。

## 已确认要求

1. 服务在现有 `Scanner.Web` 中提供，通过 Web 页面操作。
2. FedEx、USPS 业务配置从数据库读写，管理员可在界面修改。
3. 日常配置不依赖手动修改 XML；保存后下一次查询直接使用新配置，无需重启。
4. 分开记录预报来件、承运商状态和仓库实收，支持查找收货差异。

数据库连接本身继续沿用现有 Web 启动配置；“配置存数据库”指承运商业务配置。当前 WPF 实验版 FedEx 查询的环境变量设置没有迁移，也没有改为调用本 Web 服务。

## 数据来源与接口前提

系统需要两类独立的数据：

| 数据 | 用途 | 来源与限制 |
| --- | --- | --- |
| 应收/预报运单清单 | 知道有哪些包裹需要跟踪 | 客户或 RMA 预报；后续也可接入获授权的承运商来件数据 |
| 承运商追踪状态 | 判断某个已知运单是否显示送达 | FedEx / USPS Tracking 接口，受凭据、查询权限和额度限制 |
| 仓库逐件实收 | 证明仓库实际扫描收到该包裹 | Web 扫描登记；后续可接 WPF/PDA |

普通 Tracking 接口查询已知运单号，不等于可以按仓库地址获取全部来件。没有预报、没有仓库扫描、也没有承运商数据源的运单，当前系统无法发现。

因此第一版可以解决“已登记运单的运输与实收差异”，完整覆盖所有来件仍需补齐预报或承运商清单来源。FedEx 账号级订阅是否覆盖客户自行购买面单的来件、USPS 能否提供适用的收件数据和授权，均需另行确认，不能按默认具备处理。

## 第一版范围与对账规则

管理员可分别配置两家承运商的启用状态、测试/正式环境、Client ID 和 Client Secret。业务人员在当前版本中也需管理员权限才能进行预报、实收登记和物流查询；如要开放普通仓库人员，需要后续细分权限。

| 仓库实收 | 承运商显示送达 | 页面结果 | 处理建议 |
| --- | --- | --- | --- |
| 有 | 任意状态 | 已实收 | 保留首次收货时间与人员 |
| 无 | 是 | 显示送达但未实收 | 高亮提醒，核查投递位置、交接录像和内部待处理区 |
| 无 | 否或尚未查询 | 待收货 | 查看最后查询时间，按需更新状态 |

“待收货”不代表承运商一定还未送达，可能尚未查询或状态已过期。查询失败不清除旧结果，页面显示的最后查询时间是最后一次成功查询时间。

## 管理员配置与数据设计

| 数据表 | 保存内容 |
| --- | --- |
| `carrier_settings` | 所属域、承运商、启用开关、测试环境、Client ID、加密密钥、配置版本、最后修改人和时间 |
| `carrier_receiving` | 所属域、承运商、运单号、RMA/备注、登记时间与人员、首次实收时间与人员、承运商最新状态、是否显示送达、最后成功查询时间 |

配置按“所属域 + 承运商”唯一；运单按“所属域 + 承运商 + 运单号”唯一。不同域的数据隔离，重复收货扫描不会覆盖首次实收时间和人员。

Client Secret 加密存储，不通过读取配置接口回传；界面只显示是否已保存。密钥留空表示保留原值，可明确清除。修改配置保存版本号，过期版本拒绝覆盖，要求重新加载。

第一版只保存最新运输状态、首次登记与实收信息，以及配置最后修改信息；尚无完整运输事件历史、配置变更历史、收货撤销或纠错流程。

## 页面与接口

入口：登录 `/account.html`，打开“FedEx / USPS 收货对账（管理员）”，页面为 `/carrier-receiving.html`。
所有接口要求有效账户会话和 `system.configure` 权限。配置、运单均按账户所属域隔离。

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/carrier-receiving/settings/{carrier}` | 读取配置，不返回密钥明文 |
| `PUT /api/carrier-receiving/settings/{carrier}` | 保存配置，验证版本与凭据填写规则 |
| `GET /api/carrier-receiving/items` | 分页读取记录，支持运单/RMA 搜索 |
| `POST /api/carrier-receiving/items` | 登记预报或首次实收 |
| `POST /api/carrier-receiving/track` | 查询已登记运单，更新最后成功状态 |

`carrier` 为 `fedex` 或 `usps`；接口使用现有账户 Bearer 会话，不允许仅凭设备上传密钥修改承运商配置。

## 部署

1. 使用现有 Web 数据库连接，在该 MySQL 数据库执行 `Scanner.Web/Database/022_carrier_receiving.sql`。脚本仅创建两张新表，不改现有业务表。
2. 部署 Web，确保进程对部署目录下 `App_Data/carrier-keys` 有读写权限。该目录保存 Data Protection 密钥，须限制操作系统访问权限、备份，并在发布/迁移时保留；多实例须共享同一目录和应用名。数据库恢复时也需恢复密钥。丢失密钥可在管理页面重新填写承运商凭据。
3. 管理员在页面分别填写 FedEx / USPS 的 Client ID、Client Secret、测试环境与启用开关。配置存 MySQL，密钥使用 Data Protection 加密；API 不回传密钥。无需修改 XML、环境变量或重启服务。Web 原有数据库连接配置仍沿用现有方式。

测试环境默认开启。正式使用前切换环境，确认凭据及查询权限。密钥留空保留原值；勾选清除密钥时需同时关闭启用；更换 Client ID 应同时填写对应密钥。配置保存具有版本冲突检查，冲突后重新加载。

## 流程与边界

- 收到客户回寄运单/RMA 时登记“预报来件”。无预报的实际来件可直接登记“仓库已实收”。重复登记保留首次记录、备注及实收时间，不覆盖历史人员。
- 点击“查询物流”以当前数据库凭据请求承运商；仅成功响应才更新状态和最后查询时间。查询失败显示错误，保留旧状态。
- 点击“登记实收”或在收货表单选择实收，记录服务器 UTC 时间和当前操作人。
- 显示送达但无实收时间时高亮，属于待核查差异，不认定为丢件。最后查询时间用于判断状态新旧。
- 列表每页最多 100 条，可搜索运单/RMA，下一页使用 ID 游标，搜索按钮返回首页。
- 本版是人工触发查询；未接定时轮询、承运商 Webhook、WPF/PDA 扫描自动关联、整板清单获取或地址级收件发现。未知运单不会凭空进入系统，完整性依赖预报或承运商另行授权的数据源。
- FedEx 采用 Track v1，USPS 采用 Tracking v3r2。账号须具备相应权限；没有真实凭据时仅能进行模拟接口验证，不能宣称已完成生产联调。

官方接口参考：
- https://developer.fedex.com/api/en-us/catalog/track/v1/docs.html
- https://developers.usps.com/trackingv3r2
- https://developers.usps.com/Oauth
- https://www.usps.com/business/api-access.htm

验证命令：`dotnet run --project tests/CarrierReceiving.Tests`。数据库迁移和真实承运商请求需在目标部署环境另行验证。

## 后续阶段与待确认事项

1. **真实接口接入**：准备两家承运商的有效开发者凭据和 Tracking 权限，验证测试环境、正式环境及实际返回结构。
2. **补全应收清单**：确认面单由公司统一提供还是客户自行购买，RMA 是否已有回寄运单号，决定从哪个系统同步预报。
3. **自动发现来件**：向承运商确认账号/地址关联范围、数据完整性、授权、费用与可用接口，再确定是否接入账号级订阅或其他来件数据源。
4. **自动跟踪与提醒**：确定轮询间隔、查询额度、送达后等待实收的合理时间、异常提醒渠道；届时相关参数也应在数据库与管理员页面维护。当前尚未实现定时任务或提醒。
5. **接入现场扫码**：将 WPF/PDA 运单扫描与 Web 实收关联，补充交接批次、照片/录像索引、异常处理结果和必要的纠错审计。

这些是后续实施方向，不代表已经接通或已经获得承运商授权。当前先保留文档与代码，不执行数据库迁移、发布或真实承运商调用。
