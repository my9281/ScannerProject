# 良品区操作 SOP

更新：2026-10-21。适用应用：**Scanner.AndroidTester（壹仓 PDA）**，配合 WPF“查看良品区”和“自动匹配”。本文覆盖 SN 入托、上传、核对、良品区内换托/移库及后续衔接；不代替设备检测合格判定。

状态：按代码补齐系统操作段落，待现场验收。现场准入、移库授权、双人复核和交接记录规则尚待明确，见第 9 节。

## 1. 作业前准备

1. 使用正确的 PDA 应用，确认网络和设备日期、时间、时区正确。首次安装见 [系统使用与维护](../系统使用与维护.md)。
2. 根据现场已确认的待处理清单找到设备，核对实物 SN、当前托盘与作业目的。系统页面叫“良品区”，不等于扫描后自动取得合格或可售资格。
3. 确认托盘实际编号为 **1–100 的整数**，箱上 SN 可读、可扫描。这里的托盘号不能直接当作货架库位编号。
4. 打开首页“良品区扫描”，先查看待上传列表及数量；有上一项作业未上传时先核实处理，不直接覆盖或清数据。
5. 扫码枪设置为键盘输出、以 Enter 结束。此页面只收 SN，不按 SKU→SN 成对扫描，也不扫描运输单号或库位码。

## 2. PDA 按钮对照

PDA 当前默认英语，可在首页切换 English / Español。中文名称用于本 SOP 说明，界面以所选语言显示。

| 中文含义 | 英语界面 | 用途 |
| --- | --- | --- |
| 良品区扫描 | Scan good stock | 首页进入 SN 托盘归属作业 |
| 托盘号 | 页面中 1–100 的数字框及上下箭头 | 设置后续扫描记录的托盘号 |
| 记录 | Record | 手工输入后提交；扫码枪 Enter 也可提交 |
| 上传 | Upload | 上传当前全部待上传记录，可能包含多个托盘 |
| 完成 | Done | 返回上一页，不等于上传或完成系统上架 |

## 3. 首次入托扫描

1. 在数字框输入或用上下箭头选择当前实物托盘号，核对后将焦点放回 SN 输入框。
2. 对准该设备的 SN 条码/二维码扫描；也可完整输入 SN 后点击“记录”。保留前导零，不以尾号代替完整 SN。
3. 每次提交后检查已记录提示和列表中的 **SN、托盘号、扫描时间**。记录增加后再扫描下一台；没有成功提示不要只凭扫码枪响声认为已经保存。
4. 扫完整托后按实物核对 SN 明细及数量。扫描值去首尾空白，长度为 1–100 字符；本次应用运行内不区分 SN 大小写去重。
5. 换下一托前先核对并上传当前托盘是更便于交接的做法；如连续扫描多托，每次切换数字框后确认新记录显示正确托盘号。

**更改数字框只影响后续新扫描，不会修改列表中已经记录的托盘号。** 当前页面没有逐条删除或修改已记录托盘的入口；错扫、错托先停止，按第 7 节处理。

## 4. 上传并核对结果

1. 扫描暂停后，核对整个待上传列表，不仅核对数字框当前所示托盘。点击“上传”会发送当前待上传快照中的全部记录，可能涉及多托。
2. 点击 Upload，等待结果。系统按每批最多 1000 条上传，确认成功的记录从待上传列表移除。
3. 全部成功后核对成功条数及待上传数量为 0。若发生部分失败，已经确认的批次已移除，其余保留；以剩余列表为准重试，不重新扫描已确认记录。
4. 在 WPF 打开“良品区 → 查看良品区”，打开或刷新后重新下载服务端数据，选择对应托盘核对 **完整 SN、托盘号、数量**。列表按托盘筛选，数量相同也要核对 SN，不能只比总数。
5. WPF 未显示时先核对刷新、环境地址、托盘和网络。上传确认与当前归属不是同一个判断：较旧扫描可能未覆盖新的归属，应交由维护人员核对记录时间。
6. 全部确认后才结束本次应用或进行安装升级。

良品区待上传记录只在内存，应用强退、系统杀进程、重启或清数据会丢失。上传失败时保持当前应用运行，恢复网络后点上传重试。返回首页的 Done 不清空本次运行去重集合，也不能当作重新开始。

## 5. 良品区内移库 / 换托盘

### 5.1 适用范围与限制

这里的“移库”指 **设备仍处于有效良品区，把 SN 从源托盘 A 改归目标托盘 B**。当前没有独立移库页面，通过在目标托盘下重新扫描并上传新记录实现归属更新，不是两托整托一键互换。

前提：新版服务及有效 SN 唯一索引、扫描回执、设备周期等迁移已由维护人员核验。未确认部署状态时，不能按新代码推定生产已具备该行为。

以下情况不套用本节：

- 已正式上架的设备从一个货架库位移动至另一个库位：当前未找到该专用流程，应先由负责人确定处理方式。
- 已上架设备重新进入良品区：新扫描可能开启新的业务周期，不是普通移库，应确认真实返修/重新入区原因。
- 仅扫描库位标签：这只登记库位主数据，不关联 SN，不更改设备托盘归属。

### 5.2 操作前核对源与目标

1. 在 WPF 刷新当前有效良品区数据，记录拟移动的完整 SN、源托盘 A、目标托盘 B 及数量。源托与目标托均按实物核对，不凭记忆选编号。
2. 现场确认哪些设备允许搬移、目标托盘可接收，并安排同一批 SN 只由一个作业人/设备处理，避免并发重复移库。
3. 检查 PDA 是否还有待上传；有记录必须先上传并在 WPF 核对完成。如果已有错托记录，先按异常处理，不把错误记录当正常作业上传。
4. 若该 SN 本次应用运行中已经扫过，即使已经上传成功，重新扫描仍会提示重复。**仅在全部待上传为 0、已在 WPF 核对且无其他未完成作业后**，结束该应用进程并重新打开，使本次运行去重重新开始；只返回首页不够。不卸载、不清应用数据，不以重启解决尚未上传的记录。

### 5.3 按目标托盘重新扫描

以下为基于现有功能的换托操作顺序，搬运授权与签字角色由现场确认后执行。

1. 在新的扫描作业中，将“托盘号”设置为目标 B，先检查数字，再放回扫描焦点。
2. 按已核对清单把设备移至目标托盘，每台在放入目标托时扫描完整 SN，核对列表显示目标 B；不得先把不确定会搬走的整批设备扫描到 B。
3. 扫描完成，逐台核对目标实物与本次列表。若移动范围变化、错扫或目标改动，先停止，不直接上传有差异的列表。
4. 点击 Upload，处理所有未确认记录直到待上传为 0。上传失败期间保留应用和移库清单，告知交接人员实物已移动但系统未确认，防止继续按旧位置取货。
5. WPF **刷新服务端数据**，分别查源 A 与目标 B：移动的 SN 不再出现在源托，全部出现在目标托；未移动的源托设备仍在源托。
6. 同时核对源托减少数、目标增加数及有效良品区总量不变。发现未更新或重复有效记录时暂停交接，由维护人员检查时间、迁移和并发记录，不直接删数据。
7. 保存本次移库记录，建议至少包含 SN、源/目标托盘、数量、实际移动时间、操作者、复核者、上传结果及异常；采用的正式记录载体和保管期限待现场确定。

示例：源托 3 有 5 台，将其中 2 台移到托 8。把 PDA 托盘号设为 8，只扫描这 2 台；上传刷新后，托 3 保留其余 3 台，托 8 增加这 2 台，良品区总量不变。3、8 和数量仅为示例。

### 5.4 需要特别复核的联动

- 服务端在同一有效周期内依据扫描时间更新托盘，旧时间记录可能不覆盖较新归属。各 PDA 时间须校准，不允许通过把设备时间调到未来“强制移库”。
- 原上传记录重试沿用原扫描标识，是补发确认；真正换托需重新扫描产生新记录，不能把重传旧数据当作移库。
- 当前未发现换托时自动同步已生成工单 location 的联动。移库后平板可能仍显示旧工单位置；不能仅因 PDA 成功就认定工单位置已更新。
- 自动匹配的来源键包含扫描资料，重新扫描后再次自动匹配可能被识别为新来源。已生成工单的设备先由负责人核对旧任务和目标位置，不直接重复生成工单来修正位置。

## 6. 与检测工单和上架的衔接

PDA 上传只登记有效良品区归属，不表示完成检测、完成工单或完成正式上架。

1. WPF 导入已核对的基础表，通过“自动匹配”获取并匹配良品区资料；匹配出的待检测明细会触发工单上传。
2. 工单接收账号由服务端配置，默认 my9281；平板只读当前登录用户审核位为 0 的工单，因此要确认接收账号和实际操作人一致。
3. 平板的“完成”开关修改需点击保存并收到确认；完成状态与上架审核位不同。检测过程的现场填写标准另按对应 SOP。
4. 进入上架前按 [上架 SOP](上架SOP.md) 进行检测/翻新、贴标、SKU/SN 配对及打托等操作。上架用的“SKU / SN 扫描”是另一模块，不能拿良品区纯 SN 列表直接充当配对批次。
5. 正式上传上架后，服务端归档对应良品区记录并更新当前周期工单审核位；这不是物理删除历史。待确认托盘不能仅为了移除列表而提前上传上架。

## 7. 异常处理

| 情况 | 操作要求 |
| --- | --- |
| 同一 SN 提示重复 | 停止重复扫描，检查本次运行是否已记录/已上传；跨托更正按第 5 节，不能只改数字框 |
| 已记录了错误 SN、错误托盘或错扫运输码 | 暂停扫描，保留页面和实物核对资料；当前无单条编辑/删除入口，由负责人制定受控重扫/更正方案。不能为清除一条错误直接丢掉整批未上传数据 |
| 上传超时、断网 | 保持当前应用运行，核对剩余待上传，恢复网络后原记录重试；不重扫生成另一组记录 |
| 错误记录已上传 | 先核对服务端当前归属；真实 SN 的换托可按移库规则更正，误录的非设备编号没有已确认的操作员删除流程，交维护人员核查 |
| 应用被杀或设备重启 | 先在 WPF 刷新查哪些已到服务器，再按实物盘点缺失；未上传内存记录不能承诺自动恢复 |
| WPF 数据仍是旧托盘 | 刷新、核对环境及 SN 时间；检查并发作业和设备时钟，不能反复换时间重扫 |
| 移库后工单仍在原位置 | 先记录源/目标及工单 ID，交负责人处理；不要用完成开关、审核位或重复生成任务替代位置更正 |
| 设备已上架却想换货架库位 | 不按本 SOP 新扫入良品区；缺专用已上架移库流程，交负责人确认 |

## 8. 作业结束检查

- [ ] 本次每台实物 SN 与正确托盘对应，待上传为 0，WPF 已刷新复核。
- [ ] 移库时源托、目标托和总量核对通过，无多余、遗漏或重复有效 SN。
- [ ] 已生成工单的位置差异已记录并交接，不将其视为自动同步。
- [ ] 未确认上传、错扫错托及实物/系统差异有明确接手人；未解决前不标为移库完成。
- [ ] 本次记录按现场要求留存，之后才结束应用、换班或安装更新。

## 9. 仍缺的现场流程

| 项目 | 需要补齐的内容 |
| --- | --- |
| 良品区准入/退出 | 什么状态可以入区、谁放行、设备分区及待检与合格是否分开 |
| 移库批准与交接 | 谁发起/批准/搬运/复核，是否双人，记录表和保管期限 |
| 托盘与真实库位 | 托盘号分配、复用、防冲突及物理库位映射；整托移动是否只记台账 |
| 已生成工单后移库 | 谁更正 location、如何通知检测人员、如何避免新来源重复工单；现有 PDA 不自动完成 |
| 已上架库存移库 | 库位到库位、拆托/并托/整托移动的系统入口及库存履历；当前不能套用重新入良品区 |
| 错扫与待上传更正 | 无单条删除/编辑时，错误列表的受控重建、实物清点及已上传误码处理 |
| 返修重新入区 | 谁确认真实新周期、旧上架/旧工单如何衔接，不能与普通换托混用 |
| 实物容量与安全规则 | 机型重量、堆叠、混托和破损设备处理标准 |

代码核对依据：NativeScanPage、PalletScanSession、PalletScanApiService、PalletScanRepository 及保留数据部署记录。本次只写文档，未增加独立移库功能，也未执行现场移库测试。
