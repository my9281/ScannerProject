# Camara.WPF 开始维修录入

## 功能范围

在 `WPF.Camara` 主窗口右上角点击“开始维修录入”，打开独立窗口。仅记录 SN、SKU、首个编码的录入时间及“开始维修”动作；不联动运单收货、库存入账、工单状态、维修完成或 Web 看板。

## 使用

1. 扫描或输入 SN，回车转到 SKU；也可先录 SKU。
2. 录入 SKU。两项去首尾空白后各为 1–50 个字符，且不能包含控制字符，才可提交。保留前导零，不截断过长编码。
3. 核对两项，点击“确认开始维修并上传”。SKU 回车仅将焦点移到确认按钮，不自动上传。
4. 只有服务器返回本条记录编号和“开始维修”确认，才清空输入并回到 SN，准备下一台。

SN 和 SKU 可分别清除。首个非空编码开始录入时计时，后续补码或只清除一项保留此时间；两项全部清空后重新计时。界面显示本机时间，上传按 UTC 保存，设备时钟应正确。

## 服务配置

使用现有 Web 接口 `POST /api/repair-scans` 和 `X-Upload-Key`。主窗口的标签打印配置不受影响。

在录入窗口展开“连接设置”，填写 HTTPS 服务地址和现有 Web 上传密钥。此处输入只在当前窗口有效，不自动保存密钥。也可由管理员修改程序目录中的 `repair-upload.xml`；该文件随构建/发布复制，默认密钥为空。

环境变量 `SCANNER_UPLOAD_BASE_URL`、`SCANNER_UPLOAD_API_KEY` 分别优先于 XML 对应值。支持服务地址中的虚拟目录，禁止自动重定向。配置文件含密钥时应限制文件访问权限。

## 失败和恢复

点击上传时先将记录保存到 `%LOCALAPPDATA%/ScannerProject/Camara/repair-start-pending.json`，然后发起请求。未确认成功时锁定编码和原时间，允许调整连接设置并重试；重开窗口或重启程序后恢复同一条待上传记录。

同一条记录的重试复用 `scanId`，服务器不重复插入；再次开始一台设备的维修会使用新编号，因此同一 SN 可以有多条维修开始记录。待上传文件读取异常时阻止录入，保留原文件供排查；同一个本地记录文件只允许一个窗口/进程使用。

尚未点击上传的输入仅在窗口内保留，关闭后不恢复。已发起上传但结果未知时，不应手动删除待上传文件再重录，以免产生新的业务记录。

## 部署与验证

- 复用 [021_repair_scan_records.sql](../Scanner.Web/Database/021_repair_scan_records.sql)，不新增表结构；尚未建表的环境需先执行该脚本，再部署支持此接口的 Web 和新版 Camara.WPF。已有表无需再次迁移。
- 录入状态由服务器固定为“开始维修”。表结构和原接口说明见 [扫描记录说明](../Scanner.Web/Database/repair_scans.md)。
- 自动检查：`dotnet run --project tests/RepairScan.Tests`，覆盖服务端输入边界、WPF 首扫时间与清空、待上传恢复、重试编号和响应确认。
- 打印回归：`dotnet run --project tests/WpfCamara.Tests`。
- 实际数据库写入、真实扫码枪焦点及现场服务连通性需在部署环境验收。本文不代表已执行线上 SQL 或已部署服务。
