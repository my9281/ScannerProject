# PDA 包裹收货与待执行 SQL

更新日期：2026-11-19。PDA 项目：`Scanner.ShippingCowAndroid`，菜单“包裹收货”使用配置自动登录。

## 使用方式

1. P0收货直接使用收货账号所属域，不依赖BLUETTI站点配置或预报工单。需同时发布本次Web与PDA，旧版Web仍可能要求预报站点。
2. PDA 包裹收货页已于2026-11-19改为配置账号自动登录，不再显示登录框。在 `Scanner.ShippingCowAndroid/appsettings.xml` 填写 `ReceivingPassword`，默认 `ReceivingUsername=PDA01`、`UploadBaseUrl=https://wms.ymforever.com/`，重编译安装后生效。账号需在 Web 中预先创建；后台读取服务器确认的用户 ID、域与站点，只读账号不能收货。
3. 扫描运单条码后按扫描枪回车或点“记录”。PDA 自动识别承运商，先保存到本机并在表格显示识别结果。首次未连接、离线、上传期间和重复扫码时仍可录入。
4. 离线时可继续扫描，退出页面或重启应用后恢复原批次、设备 ID、扫描 ID 与待上传记录。
5. 联网后点“上传”。每次最多100条，后台按扫描ID核实确认结果，表格标为“已上传”，只提示“上传成功”或“上传失败，请重试”。不在上传前请求预报、不在上传后切批次或重新配置身份。必要的会话续登、幂等确认和本地保存仍在后台处理。
6. 上传成功后表格不清空，本机保留最近5000条已上传记录、全部待上传记录及待重扫记录。同一包裹重复扫描也逐次保留审计事件。

FedEx 普通数字运单码直接记录；以 `96` 开头的 34 位路由条码去掉前 7 位；`[)>` 长组合码提取 31Z 字段中的完整 27 位单号。USPS 识别常见的 20 或 22 位、`91`–`95` 开头数字单号，以及以 `US` 结尾的 13 位国际件单号。UPS `1Z`、地区标识及无法识别的格式在本机保留为“请重扫”，并播放警报音。普通码去首尾空白并统一大写，原始扫码内容完整保留。

按现场要求，打开收货页时若历史待上传缓存不符合当前校验规则（例如旧运单号与原始内容不一致），直接清空本机收货历史、待上传记录及去重状态并开始新批次，不再因这类错误阻止进入页面。此操作不删除服务器记录；正常缓存继续保留。

新增现场识别规则：`420089014134` 等 `420` 开头、8或12位的纯数字地区码保留为报警行，不上传为包裹。现场确认的 FedEx `420` 开头30/34位完整路由条码按 FedEx 记录，保留全部数字，例如 `420089019234690213424550799901` 不截掉前8位。`TBA` 开头自动单独标记为 TBA，服务端接受实收登记，列表也显示 TBA；这不增加 TBA 物流轨迹接口。Web版本为 `receipt-carrier-codes-20261119-v5`，需同步更新PDA与Web，无需新增SQL。

分隔符修复版 `receipt-scan-separators-20261119-v6`：识别和校验时忽略扫码传输的 GS/RS/FS/US/EOT/TAB 分隔字符，原始扫码内容不变。例如 `42008901` + GS + `9234690213424550799901` 规范为完整号码 `420089019234690213424550799901`，不会误报。旧版已标红的记录保留原状态，可单独删除后重扫。

主界面与收货页面均提供本机记录列表、每行“删除”和“清除缓存”。删除单条会同时移除该条本机待上传记录；清除缓存会清空本机全部收货记录并开始新批次。服务器上已上传的记录不会被删除。正在上传时暂不允许删除或清空，以免与上传确认冲突；仍可继续扫描。缓存无法读取时，主界面直接显示“清除收货缓存”，无需进入收货页即可恢复。

## 身份、缓存与重试

- 专用账号 `PDA01` 登录成功后可直接调用收货身份和上传接口，不因普通角色缺少 `receiving.write` 被拒绝；此授权不授予系统配置权限。服务器按该会话的用户和所属域登记PDA收货，不依赖客户端缓存中的人员或域字段。接口版本 `receipt-pda-access-20261119-v4`，需发布 Scanner.Web 后生效。

- 使用 Bearer 人员会话，收货接口不接受共享设备上传密钥作为人员身份。
- 密码不落盘；会话令牌使用平台 SecureStorage 保存，并绑定服务器地址。本机收货队列不包含密码或令牌。
- 每条记录固定原操作人、域、站点、设备与批次。未上传时不能切换到其他人员/域/服务器，也不能直接清空或开始新批次。
- 登录过期后可按已确认的本机身份离线记录；联网时使用配置自动重新认证，上传遇到401最多再认证并重试一次，不无限循环。明确403拒绝后暂停该身份。服务器始终检查当前账号是否仍有收货权限。
- 用户和域是上传授权边界，内部收货范围固定为 `domain-{域ID}`，与客户预报站点解耦。旧离线记录保留原范围字段，不因后续预报配置变化而拒收；服务器仍校验当前域、原操作人及不可变扫描内容。切换配置账号时如有原账号待传记录，需先改回原账号配置完成上传，不能自动转移。
- 缓存损坏时保留原文件，禁止静默重建并丢失数据。模块延迟初始化，错误不会阻止其他 PDA 功能启动。
- 客户端磁盘写入或服务器确认不完整时均保留原扫描 ID，可重复发送。不要卸载应用或清理应用数据来解决待上传问题。
- 待上传最多5000条，上传期间暂停扫码。内部批次仅作审计记录，使用者无需操作；上传不会切批次，容量达到限制时在后续新扫描中管理内部批次。

## Web 接口与记录

| 接口 | 权限 | 用途 |
| --- | --- | --- |
| `GET /api/carrier-receipts/context` | `receiving.write` | 获取当前人员、域及站点 |
| `POST /api/carrier-receipts` | `receiving.write` | 事务提交 1–100 条扫描，返回全部确认 ID |
| `GET /api/carrier-receipts?page=0&search=` | `receiving.read` | 查看实收扫描事件，按运单或批次搜索 |

普通用户与管理员有收货、查看权限；只读用户只有查看权限。Web 账户页新增“PDA 包裹实收记录”，页面为 `/carrier-receipts.html`。

服务端保存不可变扫描事件，校验同一扫描 ID 的全部原始内容；ID 冲突或任一记录无效时整批不确认。无客户预报的包裹也允许实收，不阻塞收货。后续客户预报同步后，记录页面通过运单关联显示“已关联预报”，无需重新扫描。

`carrier_receiving` 保留第一次成功登记的实收信息，不因重复扫描或迟到的离线记录覆盖；所有扫描时间仍可在事件表追溯。事件条数不是唯一包裹数量。页面中的服务器确认时间是实际落库时间，不能代替设备扫描时间。
