# Tester 托盘扫描上传

新数据库执行 `Scanner.Web/Database/001_tester_pallet_scans.sql`。已有旧表的数据库先暂停上传和上架写入、备份表，再执行 `002_tester_pallet_scans_unique_sn.sql`，最后部署更新后的 Scanner.Web。迁移保留每个 SN 扫描时间最新的一条（时间相同保留最大 ID），并增加 SN 唯一索引。新建表已含该索引，不要再执行 002。复用现有 `Database` 配置，不在客户端放置数据库凭据。

Tester 主界面 → 托盘扫描 → 选择 1–10 号托盘 → 输入/扫描 SN 后回车 → 上传。
托盘号在每次扫描时固定；之后更改托盘号不修改已有记录。扫描数据暂存内存，退出应用后不保留。

接口：`POST https://wms.ymforever.com/api/tester-pallet-scans`
若服务器配置 `Upload:ApiKey`，在页面“上传设置”中填写相同密钥，经 `X-Upload-Key` 发送。密钥仅存本次运行内存。

```json
{"items":[{"scanId":"84cd2c29-548c-40eb-aac8-a1b72b0c5f81","sn":"001234","palletNumber":1,"scannedAt":"2026-10-03T10:20:30.123+08:00"}]}
```

成功返回 `{"acceptedScanIds":["84cd2c29-548c-40eb-aac8-a1b72b0c5f81"]}`。
每批 1–1000 条，客户端自动分批。SN 为 1–100 字符；托盘号必须为整数 1–10。Tester 对本次运行中已扫描的 SN 去重，上传成功后也保留去重记录，重启应用后重置。服务端以 SN 唯一索引去重（比较规则沿用数据库列排序规则），已有 SN 更新扫描日期、扫描时间和托盘号，保留原有自增 ID 和 scan_id。同一批多次出现同一 SN 时最后一条生效；后上传的数据覆盖当前值，不比较扫描时间新旧。

表 `tester_pallet_scans`：自增 BIGINT `id`、`sn`、DATE `scan_date`、INT `pallet_number`、DATETIME(3) `scan_time`，以及用于重试去重的唯一 `scan_id`。
日期和扫描时间来自设备扫码当时的本地时间，保留当地钟面值（不转换成服务器时区），毫秒精度。日期不是上传日期。

每批事务写入。同一 SN 重试不会重复插入；现存 `scan_id` 如果用于其他 SN，整批回滚并返回 400。服务器确认整批后客户端才移除相应记录；失败批次保留，可重试，已完成批次不重传。上传期间新扫描的数据留待下一次上传。

上架接口写入 `shelved_pallet_data` 后按 SN 删除 `tester_pallet_scans` 中对应记录，两项操作共用同一个 MySQL 连接和事务；整批任意操作失败都回滚。没有对应扫码记录时仍可上架。两张表必须使用 InnoDB。上架后的新上传仍可再次创建扫码记录。外部通知在事务提交后执行，不属于数据库事务。

本地验证不向生产 API 写入测试数据。上线需先执行建表脚本并发布 Web 服务，再更新 Tester。
