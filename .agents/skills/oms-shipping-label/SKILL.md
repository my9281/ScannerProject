# OMS 网页辅助填写与人工审核

适用站点：`https://ntm8zfn.oms.eccangtms.com/`。**默认只在用户可见的网页中辅助填写，填好即停，由用户人工审核和提交。** 不把“帮我填写”“再做一单”理解为自动试算、收费下单或打印授权；不切换成后台 API 或 WPF 代替用户当前网页。

## 默认交付：填好，交给人审

打开或接续用户的 OMS 页面，根据资料填入字段，保持页面可见。填写完成后核对页面值，简洁列出客户单号、收件人、地址、箱数、尺寸重量、渠道、币种和发件地址，提供截图，将当前网页留给用户审核。

默认**不点击任何保存、提交、立即下单、打印标签或最终打印按钮**。不为了“把流程做完”自动越过人工审核。用户可以自行点击后让助手观察状态，也可以明确指示助手执行某一步；此时只执行所指步骤并停下，不自动串起后续动作。

## 输入和沿用规则

可从用户表格或 BLUETTI 查询结果读取日期、SN、SKU、型号、长宽高、重量、RMA、工单编号、姓名、邮箱、电话、地址。缺少尺寸/重量时不能从型号猜测。

- **客户单号**填工单编号（`afsa...`），不是 RMA 或 SN。RMA、型号、SN 用于后续面单标注。
- 地址通常为 `街道/城市/州/邮编/国家`；拆分填写，街道连续空格合并。美国 ZIP+4 只保留第一个 `-` 前的部分；邮编、电话、SN 均作为字符串，保留前导零和 SN 原有大小写。
- 收件电话含有 `ext` 分机信息时，仅填写 `ext` 前的主电话号码；不填写 `ext` 标记及后面的分机号，也不把分机号拼接进主号码。保留主电话号码，不因存在分机而将电话栏留空。
- 本工作流默认：货物类型「包裹」、申报币种 **美元 USD**、渠道 **FedEx-美东-NJ**、箱数 **1**、单位下拉最后一项 **英制(INCH/LB)**（英寸/磅，不是英尺/磅）。用户另有要求时以用户为准。
- 发件人切到「发件人信息」→右侧「选择地址」→第一条。核对实际回填内容，不把旧会话中的发件人数据硬编码为新地址。
- `L*W*H` 按长、宽、高填；单箱重量使用 LB。不要把表格工具栏的「5」（可插入行数）当作箱数。只填首行，其余空行保持空白。
- 若未提供签名、保险、COD、申报商品信息等，保持现有空值，不擅自添加付费选项。本默认流程为当前账号演示的美国境内 ground 发货。

## 用户另行指示后的可选步骤

使用浏览器工具的最新页面状态定位控件，不能复用旧元素编号。表格式包裹编辑器可能需要点击第一行「箱数」后输入，并按 Tab 依次填重量、长、宽、高；点击表格外核对提交值。

1. 如果页面已显示「下单成功」或有现成订单 ID，不再提交或付款。只有用户要求获取/打印面单时，才继续对应步骤。
2. 用户只要求填写时，填写并核对 USD、NJ、INCH/LB、收件人和发件地址后即停。
3. 用户明确说“点击提交/试算”时才点击「提交」，显示「费用详情」后停下，记录产品、金额、币种、重量、地址类型和分区，不接着点击「立即下单」。
4. 「立即下单」是实际收费步骤。执行前说明当前金额，并确认现有用户授权涵盖该单及费用；未给定费用上限且尚未确认本次报价时，展示费用画面并请求确认。旧单授权不能用于新单。
5. 点击一次后等待「下单成功」或明确失败；超时/结果不明时先查订单列表，不能重复点击或自动重试收费接口。
6. 下单成功后记录金额、客户单号/订单 ID，停下交给用户。只有用户要求获取面单时才点击「打印标签」；只有用户明确要求实物打印时才发送打印任务。需要三行标记时，不在网页窗口打印未标注的原件。

只有用户要求 API 调查或开发时，才读取 [references/api.md](references/api.md)；这些资料不是默认操作路径或收费授权。页面资源清单只能证明地址被观察到；没有请求体/响应证据时，不称为完整抓包。

## 获取 PDF 和标注

- `getLabel` 返回的 `mergeUrl` 是原始面单地址。无需重建原来的 FedEx 条码或运单布局。
- 当前确认的下载源为 `https://erp-us-oss.eccang.com/...pdf`。仅使用当前订单实际返回的地址，不构造随机文件名。下载时不向文件存储域转发 OMS 认证头。
- 校验 PDF 文件头、收件人、地址、运单号和纸张。标注仅适配**单页纵向 4×6 英寸**的已验证 FedEx 模板；布局不同则先检查，不能盲套坐标。
- 三行依次为 **RMA / 型号 / SN**。位置为**上方收件信息右侧空白**，不是下方 TRK 运单号旁。原 PDF 为 288×432pt，标注 x=170pt、首行上缘约 y=61pt，行距 11pt，宽度 86pt。长文本可以缩小字体，不得遮盖收件地址、条码或承运商标记。
- Windows 10 1809+、.NET 10 SDK 可直接运行随附工具，不需要网站打印服务，也不需要 Python。读取 [references/tool.md](references/tool.md) 后使用 `scripts/Invoke-OmsLabel.ps1`。
- 渲染后查看 PNG，核对三行内容、位置及完整条码。导出的 PDF/PNG 都保留；未检查预览前不发送打印任务。

## 本地打印与结果

用户明确要求打印时，使用其指定打印机。已确认的常用设备是 `ZPL RP425 Rongta`；每次检查设备仍存在且状态正常。只生成文件不等于授权出纸。

- 默认 1 份，4×6 英寸，原比例。使用 Windows 驱动，不依赖 OMS 本地服务。具体命令见 [references/tool.md](references/tool.md)。
- 随附打印命令会验证驱动接受 4×6，发送前创建回执，防止误重跑。报错后检查回执和打印队列，不自动删除回执重打。
- “SUBMITTED”只证明 Windows 接收任务；队列清空不证明纸张/条码实物合格。区分已生成、已发送和用户确认已出纸。
- 从原始 PDF 的 `TRK#` 读取运单号，去掉显示用空格，保留为文本；不要把底部整段路由条码数字当作运单号。
- 简洁交付：金额（如发生下单）、运单号、输出文件、实际打印状态与份数；展示标注后的图片。不在 skill、日志或示例中保存客户真实资料、登录密码或令牌。
